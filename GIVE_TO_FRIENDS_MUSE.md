# GIVE THIS TO YOUR MUSE — FIRST MESSAGE

Hello. You are receiving a complete clipping handover pack from another Muse
(called Pax) whose owner has been running a debate-clipping operation with it.
Your owner is a friend of Pax's owner, and this pack is shared so you can run
the same system for YOUR owner — his accounts, his logos, his pages.

## What is in this pack

1. `FRIEND_CLIPPER_RULES.md` — the house clipping rules. These are binding.
   They took months of trial, error, and owner corrections to learn. Do not
   improve them, soften them, or replace them with your own style.
2. `HOW_TO_SET_UP_THE_PROJECT.md` — the plain step-by-step for setting up
   the Debate Clipper project itself, from nothing to a working system.
   Follow it in order. `INSTALL_AND_SETUP.md` is the reference behind it:
   environment facts, honest limits, and the proof tests you must pass
   before building anything.
3. `WHAT_YOU_STILL_NEED.md` — the honest list of things that are NOT in this
   pack (project code, accounts, cookies, logos) and where each one comes from.
4. `WORD_TIMINGS.md` — how the caption word timings are made (from the audio,
   never from a transcript alone).
5. `SUPERVISION_LOOP.md` + `JOB_LETTER_TEMPLATE.md` — the working loop that
   produces the quality: supervisor / builder / checker seats, one job letter
   per clip, the delivery gate. Run it for every clip.
6. `skills/` — ALL the skill folders from the original operation. Install
   them unchanged into your custom skills folder. Do not edit them during
   setup.

## What to do, in order

1. Read all three documents fully.
2. Install the skills unchanged.
3. Run the setup proof tests in `INSTALL_AND_SETUP.md` and report the results
   as files/numbers, not claims.
4. Write back the rules in your own words (a read-back), so your owner can see
   you actually understood them — especially: finished-sentence law, no hard
   split screen, no cropped faces, captions style, hook formats, and the
   checker rule below.
5. Wait for your owner's first task. Your first job is ONE test clip, judged by
   your owner. Only after he passes it do you join regular production.

## The checker rule (never breaks)

The builder never checks its own work. Build with one agent/session, then run
a SEPARATE checker (a subagent or a fresh session that did not build the clip)
that re-measures the finished file from the file itself: full decode, frame
checks at full size, caption case and timing spot checks, loudness, and a
listening audit of sentence ends. The checker writes a report file with real
numbers. No report = not done. A failed checker verdict means the clip is
fixed and re-checked, never delivered as "finished".

## Working rules

- Work as FILES, not chat claims. Every claim about a finished clip must be
  provable from the file: size, MD5 hash, frames, loudness reading.
- If something stalls or fails, say so plainly and early. Never sit silent.
- You never post anything unless your owner explicitly makes posting your job.
  By default the owner posts himself.
- One clip at a time. The owner is the final eye on every finished clip.

## What this pack does NOT give you

No passwords, no cookies, no accounts, no access to the original owner's
machines or pages. Anything of that kind is listed in
`WHAT_YOU_STILL_NEED.md` and your owner provides his own versions himself.
